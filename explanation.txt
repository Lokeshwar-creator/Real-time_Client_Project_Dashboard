The hardest problem I solved was implementing a reliable real-time client/project feed while ensuring that each user only received information relevant to their assigned role. 
The main challenge was keeping the dashboard synchronized with newly created, updated, or deleted project activities without requiring the user to manually refresh the page.
I handled the real-time role-filtered feed by combining role-based access control with real-time event updates. On the backend, I validated the authenticated user’s role and permissions before returning or broadcasting data. 
The frontend maintained the current user role and applied the appropriate filters so that users such as Admins, Managers, and Clients could see only the information relevant to them. Real-time updates were then pushed to connected clients, allowing the dashboard to reflect changes immediately. I also considered loading states, error handling, and maintaining a consistent UI when updates arrived.

One thing I would do differently is design the real-time communication and authorization layer earlier in the project. Initially, some filtering and synchronization logic became distributed across different parts of the application, making it harder to maintain. With more time, I would centralize permissions and event handling into reusable services and add more automated tests for role-based scenarios and real-time updates.
